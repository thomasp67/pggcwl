# Port Glasgow Golf Club (PGGC) — Winter Season Results Web App

A pure client-side static web application hosted on GitHub Pages that provides real-time scoring, competition management, handicap calculations, and tournament leaderboards for Port Glasgow Golf Club.

The application operates with **zero build tools** (no Node.js, Webpack, or npm required at runtime) and runs natively in any modern web browser. It supports both live web deployments (HTTP/HTTPS) and fully offline local previews (`file://`).

### 1.1 Dual-Mode Data Architecture
1. **HTTP/HTTPS Mode (GitHub Pages / Local Web Server):**
   - On startup, `app.js` fetches `config/course.json`, `config/cuts.json`, `config/prizes.json`, `config/magic2s.json`, `config/lastman.json`, `config/tabs.json`, and `data/members.json`.
   - It then sequentially fetches `data/01.json`, `data/02.json`, ... up to `data/20.json`.
   - Discovery halts upon encountering the first HTTP 404. The highest loaded week is established as the latest active round.
   - All network requests include a timestamp query string (`?v=${Date.now()}`) and `cache: 'no-store'` to prevent stale browser caching.
2. **Offline Local File Mode (`file://`):**
   - When opened directly from disk without a web server, the browser's security model blocks `fetch()`.
   - The app seamlessly detects `window.location.protocol === 'file:'` and loads the pre-bundled `window.GOLF_DATA` from `data/data.js` (generated by `process_raw.js`).

## 3. Mathematical & Scoring Calculation Engines

### 3.1 Playing Handicap Formula
Calculated dynamically for each player before every round based on their active Handicap Index ($HCI$) entering that week:
$$PlayingHandicap = \min\left(strokeLimit, \text{round}\left(allowance \times \left(HCI \times \frac{slopeRating}{113} + (courseRating - par)\right)\right)\right)$$
Since Port Glasgow Golf Club has $SR = 113$, $CR = 67.0$, $Par = 67$, and $Allowance = 1.0$:
$$PlayingHandicap = \min(36, \text{round}(HCI))$$

### 3.2 Hole Handicap Stroke Allocation
Strokes received by a player on a specific hole with Stroke Index $SI$:
$$HoleStrokes = \lfloor PlayingHandicap / 18 \rfloor + (PlayingHandicap \bmod 18 \ge SI \ ? \ 1 : 0)$$

### 3.3 Stableford Points per Hole
For hole gross score $G$:
- If $G \le 0$ (pickup, non-score, or uncompleted hole): $Points = 0$
- If $G > 0$:
$$Points = \max(0, HolePar + HoleStrokes - G + 2)$$
- **Total Points:** $\sum_{h=1}^{18} Points_h$

### 3.4 Countback Tiebreaker Cascade (Weekly Standings)
When multiple players tie on Stableford Total:
1. **Back 9:** Sum of points on Holes 10–18.
2. **Back 6:** Sum of points on Holes 13–18.
3. **Back 3:** Sum of points on Holes 16–18.
4. **Hole 18:** Points scored on Hole 18.
5. If completely tied across all countback stages, players share the tied rank (e.g., `T1`).

### 3.5 Scorecard Accordion & 0/NR Rules
When a user clicks on any player row in Weekend Stableford, Magic 2's, Player Tracker, or Par Bingo, an accordion opens showing the full hole-by-hole card:
- **Hole details:** Par, Stroke Index, Strokes Received, Gross Score, Nett Score ($Nett = Gross - Strokes$), and Stableford Points.
- **Gross 2 Highlights:** Any gross score of 2 is styled with an emerald/gold glow.
- **Mandatory Complete Round Rules for Gross & Nett Totals:**
  - A player **must register a valid score on every hole** to post a gross or nett total.
  - If a player scores 0 on any hole of the Front 9 (Holes 1–9), the **OUT** total displays **NR** (No Return).
  - If a player scores 0 on any hole of the Back 9 (Holes 10–18), the **IN** total displays **NR**.
  - If a player scores 0 on either nine, the **TOT** displays **NR**.
  - Stableford points are still earned on completed holes regardless of NRs on other holes.

## 4. Handicap Adjustment & Cut Engine (`config/cuts.json`)

All handicap cuts and increases accumulate chronologically across the 20 weeks. A player's active handicap entering Week $w$ is:
$$ActiveHCI_w = origHCI + \sum_{k=1}^{w-1} Cut_k$$
If a player does not play in Week $k$, $Cut_k = 0.0$ and their handicap carries forward unchanged.

```json
{
  "triggerPoints": 36,
  "bufferCapPoints": 43,
  "increasePoints": 30,
  "increaseAdjustment": 0.1,
  "tiers": [
    { "tier": 1, "minHci": 0.0,  "maxHci": 5.0,  "baseCut": 0.1, "cutPerPoint": 0.1, "capCut": -1.0 },
    { "tier": 2, "minHci": 5.1,  "maxHci": 10.0, "baseCut": 0.2, "cutPerPoint": 0.1, "capCut": -1.2 },
    { "tier": 3, "minHci": 10.1, "maxHci": 15.0, "baseCut": 0.3, "cutPerPoint": 0.1, "capCut": -1.4 },
    { "tier": 4, "minHci": 15.1, "maxHci": 20.0, "baseCut": 0.4, "cutPerPoint": 0.1, "capCut": -1.6 },
    { "tier": 5, "minHci": 20.1, "maxHci": 25.0, "baseCut": 0.5, "cutPerPoint": 0.1, "capCut": -1.8 },
    { "tier": 6, "minHci": 25.1, "maxHci": 99.9, "baseCut": 0.6, "cutPerPoint": 0.1, "capCut": -2.0 }
  ]
}
```

### 4.1 Adjustment Evaluation Rules
For a round with Stableford score $P$:
1. **Handicap Increase ($P < 30$):** $+0.1$ added to handicap index ($Adjustment = +0.1$).
2. **Buffer Zone ($30 \le P < 36$):** No adjustment ($Adjustment = 0.0$).
3. **Progressive Cut ($36 \le P < 43$):**
   - Active tier determined by player's active $HCI$:
     $$Cut = -1 \times \left(baseCut + (P - 36) \times cutPerPoint\right)$$
   - Capped at the tier's $capCut$.
4. **Buffer Cap Cut ($P \ge 43$):** Player receives the full tier maximum cut:
   $$Cut = capCut$$

## 5. Prize Money & Competition Configurations

The prize funds are fully driven by `config/prizes.json`:

```json
{
  "sweep": {
    "entryFee": 2.00,
    "description": "Weekend Stableford Sweep prize fund (£2 per entrant)",
    "tiers": [
      { "minEntrants": 16, "shares": [0.50, 0.30, 0.20], "description": "16+ players: 1st 50%, 2nd 30%, 3rd 20%" },
      { "minEntrants": 10, "shares": [0.65, 0.35], "description": "10-15 players: 1st 65%, 2nd 35%" }
    ]
  },
  "magic2s": {
    "entryFee": 1.00,
    "eligibility": "league_only",
    "description": "Magic 2's competition: £1 entry fee per entrant. League prize pot is league entrants x £1."
  }
}
```

### 5.1 Weekend Sweep Prize Pot Rules
- **Entry Fee:** £2.00 per entrant (open to all club entrants).
- **Total Pot:** $FieldSize \times £2.00$.
- **Payout Brackets:**
  - **$\ge 16$ entrants:** 1st place gets 50%, 2nd gets 30%, 3rd gets 20%.
  - **10–15 entrants:** 1st place gets 65%, 2nd gets 35%.
  - **$< 10$ entrants:** 1st place gets 100%.
- **Tied Payouts:** Tied players combine the prize shares for their tied positions and divide equally (e.g. 2 players tied for 1st in a 16+ field share $50\% + 30\% = 80\%$, receiving 40% each).
- Winnings are rounded to 2 decimal places and displayed as a green badge `£XX.XX` beside the player's name.

### 5.2 Magic 2's Prize Pot & Rollover Rules
- **Entry Fee:** £1.00 per entrant.
- **Total Magic 2's Fund:** $TotalEntrants \times £1.00$ (includes both open and league participants).
- **Weekly League Prize Pot:** $LeagueEntrants \times £1.00 + RolloverFromPreviousWeek$.
- **End of Season Fund:** $TotalMagic2sFund - WeeklyLeaguePrizePot$ (accumulates weekly).
- **Winner Eligibility:** **Only Winter League members** (`inLeague: true`) can win shares of the prize pot.
- **Multi-Share Rule:** Each gross 2 on an eligible hole earns 1 equal share. Multiple 2s by the same player earn multiple shares.
- **Rollover Rule:** If no eligible gross 2s are scored by league members in a week, the **entire Weekly Prize Pot rolls over** to the following week.

## 6. The Eight Competition Views

### View 1: Winter League (`#tab-leaderboard`)
- **Eligibility:** Winter League members only (`inLeague === true`).
- **Season Metric:** Ranked by the sum of each player's **Best 10 Stableford scores**.
- **Score Heatmap:** 1–10 counting scores display in an intuitive color-coded heatmap:
  - $\ge 40$ pts: Deep vivid emerald (`score-hm-40`).
  - $37 - 39$ pts: Vivid vibrant green (`score-hm-37`).
  - $34 - 36$ pts: Medium fresh green (`score-hm-34`).
  - $31 - 33$ pts: Lighter green around 33 (`score-hm-31`).
  - $28 - 30$ pts: Soft warm yellow (`score-hm-28`).
  - $27$ pts: Vibrant golden yellow (`score-hm-27`).
  - $24 - 26$ pts: Soft coral-red (`score-hm-24`).
  - $< 24$ pts: Vivid deep red (`score-hm-low`).
- **Columns (Desktop):** Pos (4%), Player Name & Strokes (18%), Total Cut (7%), Rounds (6%), Average (6%), Money Won (8%), Best 1–10 Scores (4.4% each), and Total (7%, positioned far right).
- **Columns (Mobile):** Pos (14%), Player Name (48%), Total (18%), and Hi/Lo (20%). The Cut column is omitted on mobile in favor of `Hi/Lo`, which shows the player's best score beside their 10th best score in the format `40/30` (or `38/-` if $< 10$ counting rounds, `-` if 0 rounds).
- **Interactive Sorting:** Clicking on `Pos`, `Total Cut`, `Rounds`, `Average`, `Money Won`, or `Total` headers toggles sorting:
  - **Position (Pos) & Total Cut columns:** 1st click sorts smallest to largest (`asc`, showing Pos 1 first or biggest cuts first), and 2nd click sorts largest to smallest (`desc`).
  - **Performance columns (Rounds, Average, Money Won, Total):** 1st click sorts largest to smallest (`desc`), 2nd click smallest to largest (`asc`).
  - **Subsequent clicks:** Reverse direction back and forth.
  - **Tab Switch Reset:** Leaving the Winter League tab and clicking back on it automatically resets sort to natural `Pos` ranking.
- **Info Bar:** Displays "Best 10 stableford scores" on both desktop and mobile.
- **Average Metric:** Calculated as $\frac{\sum \text{All Rounds Played}}{\text{Rounds Played}}$ (Season Average across all rounds played up to the active week, formatted to 1 decimal place).
- **Tiebreaker Cascade:** Compares 1st best score, then 2nd best, ..., down to 10th best score. Tied ranks (`T1`, `T2`) only apply if all 10 counting scores are identical.
- **Weekly Rank Movement Indicator:** Beside the playing handicap in brackets, displays week-over-week leaderboard movement:
  - Green up arrow with number of places gained (`▲N`, e.g. `▲2`).
  - Red down arrow with number of places dropped (`▼N`, e.g. `▼3`).
  - Automatically hidden if position is unchanged, for new entrants, or during Week 1.
  - Hover tooltip indicates exact movement and previous week reference.
- **Historical Week Navigation:** Allows stepping through Weeks 1 to 20 to view standings as of any past round.

### View 2: Weekend Stableford (`#tab-weekly`)
- **Eligibility:** Open to all club members.
- **Scores:** Displays full 18-hole Stableford points, playing handicap, total points, countback, and handicap cut/adjustment earned this round.
- **Points Chips:** High-contrast color-coded chips: Red (0 pts), Yellow (1 pt), Light Green (2 pts), Mid Green (3 pts), Dark Green (4 pts), Orange (5+ pts).
- **Sweep Prize:** Displays exact winnings earned beside player names formatted with a `💰` prize badge (e.g. `💰 £14.00`).
- **Scorecard Accordion:** Clicking a row opens the full 7-column scorecard (Hole, Par, SI, Gross, Strokes, Nett, Points) with equal column widths and No Return (NR) validation.
- **Columns (Desktop):** Pos (4%), Player Name & Strokes Received (19%), Holes 1–18, Total, Countback, and Cut (handicap cuts earned this round; blank if no cut). The separate strokes column is removed on desktop as strokes are directly shown beside the player's name.
- **Columns (Mobile):** Pos, Player Name & Prize Badge, Total, Cut (optimized for 360 × 760 viewports with zero horizontal scrolling; HCap column omitted for maximum clarity).
- **Info Bar:** "Individual Stableford • Number of entrants • sweep pot • click row for scorecard".
- **Filter:** "Hide Non-League" checkbox.

### View 3: Eclectic Competition (`#tab-eclectic`)
- **Eligibility:** All players (with toggle to hide non-league).
- **Metric:** Compiles each player's **personal best Stableford score on each of the 18 holes** across all rounds played up to the selected week.
- **Winner Dropdown:**
  - **Nett:** Ranked primarily by Nett score ($\text{Eclectic Total} - \text{Playing Handicap Strokes}$). If tied on Nett, sorted by Gross points, followed by standard Back 9 > Back 6 > Back 3 > Hole 18 countbacks. Selected by default.
  - **Points:** Ranked primarily by Gross eclectic points. If tied on Points, sorted by Nett, followed by standard Back 9 > Back 6 > Back 3 > Hole 18 countbacks.
- **Interactive Header Sorting:** Clickable column headers allow instant sorting by:
  - **`Pos`**: 1st click sorts Low to High (ascending: 1, 2, 3...), unplayed at bottom. Subsequent click reverses.
  - **`Rounds`**: 1st click sorts High to Low (descending). Subsequent click reverses.
  - **`Points`**: 1st click sorts High to Low (descending). Subsequent click reverses.
  - **`Nett`**: 1st click sorts High to Low (descending). Subsequent click reverses.
  - Active sort column and direction indicator (`▲` / `▼`) appear on the header. Sort resets back to natural position rank upon switching tabs or changing the Winner dropdown.
- **Columns (Desktop):** Pos (4%), Player Name & Strokes (18%), Rounds (5%), Points (5.5%, Eclectic Total Stableford points), Nett (5.5%, Points minus playing handicap strokes), and Holes 1–18.
- **Columns (Mobile):** Pos (14%), Player Name (52%), Points (17%), and Nett (17%). Total = 100% width with zero horizontal scrolling.

### View 4: Magic 2's Competition (`#tab-magic2s`)
- **Objective:** Gross 2 on 3 randomly drawn Par 3 holes (or any Par 4 / Par 5).
- **Draw Schedule (`config/magic2s.json`):** 20 combinations of 3 holes selected from the 6 Par 3s.
- **Header Banner:** Displays active drawn Par 3s, bonus Par 4/5 notice, rollover badges, and payout per 2 for the selected week.
- **Metrics Breakdown Grid:** 5 live KPI cards: Total Entrants, League Entrants, Magic 2's Fund, League Prize Pot, End of Season Fund.
- **All 2's & Rollover Table:** Displays all players who scored any 2 (both Magic 2s on drawn qualifiers and regular 2s on non-qualifiers) across the season up to the selected week with the most recent at the top (ordered descending by week). Includes Week badge, player name and handicap, Magic 2s count, Details showing all 6 Par 3 holes with color-coded qualification status, and prize won. For any week where no league member scored an eligible Magic 2, a rollover entry is rendered detailing "No Winner" along with the prize pot amount rolled over to the following week.
- **Details Column (All 6 Par 3 Holes):** Displays holes 1, 8, 11, 13, 17, and 18:
  - **Non-qualifiers (Grey):** Par 3 holes not drawn for that week. If a player scored a 2 on an undrawn Par 3, it displays a distinct `²` badge while remaining grey.
  - **Qualifiers (Green):** The 3 drawn Par 3 holes for that week where the player did not score a 2.
  - **Magic 2 (Gold):** Par 3 qualifier holes (or Par 4/5 bonus holes) where the player scored a gross 2, winning a share of the pot.
- **Columns (Desktop & Mobile):** Exactly 5 columns across all devices: Week (11%), Player Name (32%), Magic 2s (11%), Details (31%), and Prize (15%). Optimized with zero horizontal scrolling. Tapping any player row expands their full hole-by-hole scorecard accordion.

### View 5: Last Man Standing (`#tab-lastman`)
- **Survival Mechanics:** A sudden-death countdown competition.
- **Progression Order:** Default is Stroke Index 18 down to Stroke Index 1 (`si_desc`). Cycles back to SI 18 if surviving past Week 18.
- **Survival Criteria:** Must score $\ge 2$ Stableford points on the active hole to survive.
- **3 Lives System:** Missing a week costs 1 life. Surviving players who miss 3 rounds survive on their final life; a 4th missed round results in elimination.
- **Settings Controls:** Qualify Points ($\ge 2$ or $\ge 1$), Hole Order (`si_desc`, `si_asc`, `hole_asc`, `hole_desc`), Eligibility (League vs All), Starting Lives (0–5), and "Hide 0-round eliminations".
- **Table Columns:** Pos, Player Name (HCI), Status (Winner / Alive / Eliminated), and weekly target holes (Pos: 14%, Name: 54%, Status: 32% on mobile). The redundant "Lives" column has been removed; full survival history and remaining lives are viewable inside each player's row accordion.
- **Status Badges & Matrix:** Weekly visual indicators for Pass (green check), Missed with Life Saved (yellow heart), Out on Points (red score), Out on Lives (red skull), and Post-Competition (gray dash).

### View 6: Bingo (`#tab-parbingo`)
- **Objective:** First player to register a qualifying score on all 18 holes of the course wins Bingo.
- **Mode Toggle Buttons:**
  - **Gross Pars:** Hole hit when the player registers a gross par or better on that hole ($gross \le par$).
  - **Net Birdies:** Hole hit when the player registers a nett birdie or better on that hole ($nett \le par - 1$, or $\ge 3$ Stableford points).
- **Eligibility Filter:** Dropdown toggle for **League Members Only** vs **All Players (Open)**.
- **Table Balancing:** Player name column set to **20%** width in line with the other tables to maximize room for all 18 hole cells.
- **Banner:** Crowns the champion with their winning round and rounds taken, or displays the current leader and holes remaining.
- **18-Hole Matrix:** Hole columns show color-coded hit chips (gross score in Gross Pars mode; nett score in Net Birdies mode, with gross 2s and eagles/albatrosses highlighted). Displays completed Hit count and Remaining count.
- **Scorecard Accordion:** Clicking any player row opens their latest scorecard.

### View 7: Player Profile (`#tab-player`)
The Player Profile screen consolidates individual member scoring performance, season statistics, and the league-wide handicap matrix into a single unified interface. A responsive sub-view switcher at the top allows instant toggling between:

- **Sub-View A: 👤 Player Details (`#players-profile-view`)**
  - **Autocomplete Search & Quick Picks:** Instant search for any club member, plus quick-pick buttons for top active players.
  - **Profile KPI Banner:** Displays player avatar, league status, starting HCI, active HCI, cumulative season adjustment, total rounds, scoring average, best single round, Best 10 sum, and total sweep & 2s prize money won.
  - **Complete Season Record Table:** Powered by `buildPlayerRoundsTableCardHtml()`, rendering weekly rounds played with `Week`, `HCI`, `Cut`, `Strokes`, `1`–`18` points, `Total`, and `Money`. Unplayed weeks show clean dash indicators. Clicking any played row expands an interactive hole-by-hole scorecard.
  - **Quick Nav Button:** "📋 View Handicap Roster" button in the control bar allows jumping straight to the matrix view without losing context.
- **Sub-View B: 📋 Handicap Roster (`#players-roster-view`)**
  - **Matrix Grid:** Master table displaying each player's starting HCI, weekly cut/adjustment received in every round ($W_1 \dots W_{20}$), cumulative cuts, and active current HCI.
  - **Eligibility & Cuts Filters:** Filter dropdown for **All Members**, **League Members Only**, or **Players with Cuts**.
  - **Cuts Rules Inspector:** "⚙️ Cuts Rules" button opens a modal breakdown of trigger scores, buffer caps, and active tier brackets (`config/cuts.json`).
  - **Master-Detail Integration:** Clicking any player row in the matrix or tapping the "👤 Player Details" button immediately switches to Player Details with that player's complete profile and scorecards loaded.

## 7. Raw Data Processor Pipeline (`admin/process_raw.*`)

When new competition scorecards are exported from Scottish Golf:
1. Place raw CSV exports in `admin/raw/` (e.g. `members_raw.csv`, `01_raw.csv` ... `20_raw.csv`).
2. Run the processor via any of the following convenient methods:
   - **Web UI:** Open `http://localhost/pggcwl/admin/` and click the **"🔄 Prepare Data"** button or use the **"📊 Data Preparation"** tab.
   - **Windows Batch:** Double-click `admin/process_raw.bat`.
   - **PHP (Native Apache):** Run `php admin/process_raw.php`.
   - **Node.js:** Run `node admin/process_raw.js`.
   - **Python:** Run `python admin/process_raw.py`.
3. The pipeline automatically:
   - Extracts and sanitizes player names, member codes, and exact gross hole scores.
   - Updates `data/members.json` preserving starting HCIs and league flags.
   - Generates clean weekly JSON files: `data/01.json` through `data/20.json`.
   - Rebuilds `data/data.js` (`window.GOLF_DATA`) for instant zero-server offline preview.

## 9. Mobile Responsive Architecture & Progressive Accordion Disclosure

The web app is optimized for seamless, frictionless viewing on mobile smartphones (iOS Safari, Android Chrome, tested at 360 × 760) as well as desktop displays.

### 9.1 Mobile Navigation Dropdown
- **Desktop screens (> 1024px):** Displays the full horizontal tab navigation bar with 7 competition buttons (`📅 Weekend Stableford`, `🏆 Winter League`, `🎯 Eclectic`, `🪄 Magic 2's`, `⚔️ Last Man`, `🎱 Bingo`, `👤 Player Profile`).
- **Mobile & Tablet screens ($\le$ 1024px):** Horizontal tabs are automatically hidden in favor of a full-width mobile view selector dropdown (`#mobile-tab-select`). The dropdown is thumb-friendly (`44px` height), highlighted with the club's primary navy border, and synchronized bi-directionally with desktop tabs.

### 9.2 Progressive Disclosure: Initial Column Hiding (360 × 760 Optimized)
On mobile viewports, displaying 18 individual hole columns, 10 counting score chips, or redundant round counts causes horizontal scroll sprawl. The app hides detailed hole/score/round columns initially and fits high-signal overview columns within standard phone screen widths (360px–430px):
- **Winter League (`#leaderboard-table`):** On desktop, displays `Pos`, `Player Name (Strokes)`, `Cut`, `Rounds`, `Average`, `Money Won` (combined Sweep + Magic 2's), the 10 counting score chips, and `Total` at the far right. On mobile, hides columns 1–10, `Cut`, `Rounds`, `Average`, and `Money Won` to maintain zero horizontal scrolling, cleanly rendering `Pos` (14%), `Player Name` (48%), `Total` (18%), and `Hi/Lo` (20%). Both `Average` and `Money Won` are prominently displayed as summary badges inside the player's expanded accordion on tap.
- **Weekend Stableford (`#weekly-table`):** Hides Holes 1–18 and HCap. Displays `Pos` (14%), `Player Name & Prize` (52%), `Total` (18%), and `Cut` (16%).

- **Last Man Standing (`#lastman-table`):** Hides individual week columns. Displays `Pos` (14%), `Player Name` (52%), and `Status` (34% showing remaining lives ❤️ or week of elimination).
- **Bingo (`#parbingo-table`):** Hides individual 18-hole columns, Rds, and Rem columns. Displays `Pos` (14%), `Player Name` (54%), and `Status` (32% showing hit count e.g. `14 / 18` or `🎉 BINGO`).

- **Player Profile — Player Details (`#player-rounds-table`):** Hides Holes 1–18. Displays `Week`, `HCI`, `Cut`, `Strokes`, `Total`, and `Money`.

*(Note: Number of rounds played, Average, Money Won, and complete scorecards remain readily available inside each player's row accordion on click/tap).*

## 10. Administration & JSON Configuration Portal (`admin/`)

All administration tools, data processing pipelines, and raw inputs are located in the dedicated `admin/` folder (which is excluded from static hosting uploads):

- **Accessing Admin via Apache (Recommended):**
  - Simply open your browser and visit: `http://localhost/pggcwl/admin/`
  - Apache natively executes the PHP API backend (`admin/api.php`) with zero build steps or console servers required.
- **Alternative Node.js Server:**
  - Run `admin/admin.bat` or `node admin/admin_server.js` (starts a local server on port 8081).
- **👥 Members Roster Tab:**
  - Real-time search by player name or member ID.
  - Quick filters (`All`, `In League`, `Not In League`).
  - Interactive toggle switches to flip a member's `inLeague` participation flag.
  - Automatically updates `data/members.json` and synchronizes `data/data.js`.
- **⚙️ JSON Config Manager Tab:**
  - **Dynamic File Discovery:** Detects and lists all JSON configurations in `config/` (`course.json`, `cuts.json`, `lastman.json`, `magic2s.json`, `prizes.json`, `tabs.json`, plus any custom `.json` config files).
  - **🧭 Tab Order & Visibility Matrix (`config/tabs.json`):** Dedicated visual editor allowing administrators to control the **display sequence** (rearranging tabs with ▲ / ▼ order controls) and independently toggle competition tabs between **Desktop (>1024px)**, **Mobile (≤1024px)**, or **Both**. Includes live status badges, order badges (`#1`, `#2`...), and quick presets (`🏆 Winter League 1st`, `📅 Weekend Stableford 1st`, `Show All Everywhere`, `Streamlined Mobile`). When saved, sequence and visibility changes take effect immediately across desktop tab buttons and the mobile dropdown selector.
  - **➕ New Config File:** Built-in generator to create custom competition configuration files directly in `config/` with starter templates.
  - **Dual Editing Modes:**
    - **📝 Visual Form Editor:** Auto-generates structured form inputs (number steppers, boolean switches, dropdown selectors for competition rules like Eligibility and Hole Order, text fields, and structured sub-tables) so settings can be changed with no code syntax required.
    - **💻 JSON Code Editor:** Full code editor with live syntax linting, line numbers, Tab key auto-indentation, and error callouts.
  - **✨ Format / Beautify:** One-click automated 2-space indentation formatting.
  - **↺ Revert:** Restores the file to its last saved disk version.
  - **Live Synchronization:** Saving any config updates the file on disk and regenerates the offline bundle (`data/data.js`), immediately reflecting in the main application.
  - **Offline Fallback:** Also runs directly from disk via `file://`, providing a 1-click Download button to export updated configuration files.
- **📊 Data Preparation Tab & Header Action:**
  - Displays pipeline status and counts for raw exports in `admin/raw/`, generated scorecards, and members.
  - Single-click **"🚀 Process Raw CSVs & Rebuild Data"** button to execute data parsing and bundle generation directly from the browser.
